# jp-breach-deadline

個人情報の漏えい等が起きたときに、個人情報保護委員会への報告（速報・確報）が要るかどうかと、その期限を計算する小さな道具です。Node.js 18 以上で動き、外部のパッケージは使いません。

```
$ npx github:Radineer/jp-breach-deadline 2026-10-05 --malicious
事態を知った日: 2026-10-05
速報: 2026-10-08〜2026-10-10 が目安（知った後、速やかに（施行規則第8条第1項）。日数の目安は、知った時点から概ね3〜5日以内（通則編 3-5-3-3））
確報: 2026-12-03 まで（知った日から60日以内（施行規則第8条第2項・第7条第3号の事態））
```

## 計算の決まり

| 項目 | 決まり | 出典 |
|---|---|---|
| 報告が要る事態 | 次のどれかに当たるとき。1 要配慮個人情報 / 2 財産的被害のおそれ / 3 不正の目的によるおそれ / 4 本人が千人超 | 個人情報の保護に関する法律施行規則 第7条 |
| 速報 | 事態を知った後、速やかに。日数の目安は知った時点から概ね3〜5日以内 | 施行規則 第8条第1項、ガイドライン（通則編）3-5-3-3 |
| 確報 | 知った日から30日以内。第7条第3号（不正の目的）の事態は60日以内 | 施行規則 第8条第2項 |
| 日の数え方 | 知った日を1日目とし、土日・祝日も含めて数える | ガイドライン（通則編）3-5-3-4 |
| 期限の繰り延べ | 30日目・60日目が土日・祝日・年末年始閉庁日（12/29〜1/3）なら翌日 | 同上 |

- 「知った日」は、法人ではいずれかの部署が事態を知った日です（通則編 3-5-3-3）。
- 繰り延べた翌日もまた土日・祝日などに当たるときは、当たらない日まで送ります。ここはガイドラインの文言（「その翌日」）をこの道具が解釈した部分です。
- 速報の日付は、ガイドラインの目安（3〜5日）を日付に直したものです。法令が定める期限ではありません。

施行規則は e-Gov 法令 API（法令ID 428M60020000003、2026-06-14 施行の版）、ガイドラインは https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/ の原文で、2026-10-28 に確認しました。法令やガイドラインが改正されたときは、この表と試験を更新します。

## ライブラリとして使う

```js
import { deadlines, reportGrounds } from 'jp-breach-deadline';

reportGrounds({ maliciousAct: true, over1000: true });
// { required: true, grounds: [ { item: 3, ... }, { item: 4, ... } ] }

deadlines('2026-12-01').definitive;
// { days: 30, nominalDate: '2026-12-30', dueDate: '2027-01-04', shiftedFrom: [ ...年末年始... ] }
```

## 祝日のデータ

`data/holidays.json` は、内閣府「国民の祝日について」の CSV（https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv）を 2026-10-28 に取得して変換したものです（1955〜2027年）。データの無い年を渡すと、黙って間違えずにエラーで止まります。

## 注意

これは期限の計算の道具で、法的な助言ではありません。報告が要るかどうか、いつ知ったとみるかは事業者が判断します。迷うときは、個人情報保護委員会の案内（https://www.ppc.go.jp/personalinfo/legal/leakAction/）を確認してください。
